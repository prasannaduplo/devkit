01

The problem

Payfinia's payment-rail databases needed major-version upgrades without the 10–30+ minutes of hard downtime an in-place upgrade causes. The fix — AWS Blue/Green Deployments — already existed, but running it was a hand-operated shell-script process: precheck, snapshot, stand up a parallel "green" environment, validate, cut traffic over, clean up the old side. Every step was a judgment call an engineer made live.

"I can't have a maintenance window on a payment rail." — the premise this extension is built against.

03

What building it actually found

Four real, verified discoveries along the way — the kind of thing you only learn by running it against a real account.

AWS Blue/Green rejects Secrets-Manager-managed passwords
A source instance with ManageMasterUserPassword enabled fails CreateBlueGreenDeployment outright — an AWS limitation undocumented until we hit it on a real instance.
Duplo's own reconciler can delete your in-progress upgrade
The "green" instance isn't recognized as managed the moment it's created, so the tenant reconciler can reap it mid-build. Fixed with a scoped IAM Deny on duplomaster, targeting only that instance's ARN, attached and detached automatically around the risky window.
Worker-mode has a hard ~97 second ceiling
Background-worker provisioning gets cancelled by the platform's own dispatcher well before a Blue/Green deployment can finish — confirmed with hard evidence, not a guess. See below.
A ticket's token can't read its own resource
A provisioning ticket is authorized only for .../status and .../results — a plain GET on the resource itself is refused. Resuming after a retry means reading prior progress from /results, not the resource endpoint.

06

What v1 deliberately doesn't do yet

No approval gate before cutover. Runs single-shot once triggered, same as the original manual script. A pause-for-human step before switchover is the main v2 item.
No live AWS picker. Source instance and scope are typed in, not selected from a dropdown — the Add form needs a real scope picker first.
Doesn't auto-pick the target version. By design: the exact target is always user-specified, never inferred as "latest," on a database this important.
07

Anticipated questions

Does this work for anything besides MySQL?
Yes — MySQL, MariaDB, PostgreSQL, Aurora MySQL, Aurora PostgreSQL. That's the exact engine list AWS itself supports for Blue/Green, not something narrowed to one customer.
Does this compete with DuploCloud's native RDS Blue/Green feature?
No. The native path exists in the backend but is feature-flagged off and reachable only from inside the backend process itself. This extension closes that gap today using AWS's API directly.
Is this customer-specific?
No hardcoded business logic — it works against any AWS account and scope with an eligible RDS instance.
What happens if a step fails midway?
Fails fast and cleanly: the exact phase, AWS's own error message, and a full step-by-step history are all visible. A failed Blue/Green deployment is torn down automatically rather than left orphaned.
