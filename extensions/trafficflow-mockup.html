Network diagram — three layout options

Same example VPC, same traffic data, three different ways to draw it. Picking one before building the real (data-driven) version — this is a comparison mockup, not the actual extension.

public subnet resource private subnet resource database subnet resource undeclared traffic
Fits well
  • Mature libraries do the layout math (Cytoscape.js, d3-force) — least custom code
  • Natural fit for "nodes + traffic edges," which is literally the data shape
  • Handles an unpredictable number of resources without a layout rewrite
Trade-off
  • Layout is physics-based, not fixed — subnet grouping is a loose visual cue, not a hard boundary
  • Doesn't read as "the architecture diagram" someone expects from an AWS console
public subnet private subnet database subnet undeclared traffic
Fits well
  • Reads exactly like the AWS console / Lucidchart diagrams the customer actually asked for
  • Subnet boundaries are real, not a visual suggestion — directly answers "what's in which network"
Trade-off
  • Containment layout (boxes sized to fit their contents, nested correctly) is real layout code to write and get right
  • Edges crossing subnet boundaries get messy fast with more than a handful of resources
public lane private lane database lane undeclared traffic
Fits well
  • Simplest layout to implement reliably — fixed rows, no containment math, no physics simulation
  • An edge jumping sideways within a lane (like the undeclared one here) is immediately obvious
Trade-off
  • Loses real subnet geography (multiple subnets of the same tier collapse into one lane)
  • Doesn't scale gracefully much past a handful of resources per lane before rows get crowded
